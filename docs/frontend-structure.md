# Frontend organization audit and implementation

The frontend was audited and reorganized by responsibility. Forty existing files were moved. Existing implementation content, UI, props, export names, routes, API requests, state handling, validation, and CSS rules are unchanged. The backend was left untouched.

## Organization plan (implemented)

1. Keep application setup and routing together in `src/app/`.
2. Keep generic reusable UI controls in `src/components/ui/`; separate storefront and administration layouts under `components/layout/`.
3. Keep API calls, hooks, helpers, components, and feature styles within their owning feature. Group the larger admin and products component collections by workflow.
4. Keep customer route pages and the existing admin page collection as thin composition layers. Avoid adding single-file folders merely to match an architectural template.
5. Keep global tokens and cross-page styles in `src/styles/globals.css`, preserving all CSS loading order. Keep catalog styles with the products feature while retaining their existing global loading.
6. Keep existing integration tests and their setup in `frontend/tests/`; update the Vite test setup path.

## Reusable components and boundaries

| Existing piece | Consumers / responsibility | Decision |
| --- | --- | --- |
| `Button`, `Input`, `Select`, `Icon` | Used by storefront and administration flows | Retain in shared UI; reuse these controls when building future screens |
| `Drawer` | Administration navigation and mobile product filters | Retain one generic accessible drawer |
| `ProductImagesEditor`, `ProductOptionsEditor`, `ProductVariantsEditor` | Both Create and Edit | Place in admin `product-form/` |
| `CategoryPicker` | Create Details only | Place in `product-create/`; no unused shared category folder |
| `VariantPriceInput` | Imported by shared variants editor; rendered only for Create via `pricesInSek` | Place in `product-create/` under the original placement rule; retain the existing conditional usage |
| `CatalogPromo` | Home and Products pages | Keep in products `discovery/` |
| `CatalogSearch`, `CategoryNav` | Used by the storefront header | Keep product data/navigation ownership in products `discovery/`; retain the feature public exports |
| `FilterSidebar` | Desktop filters and the mobile filter drawer | Retain one component under products `catalog/` |
| `ProductCard`, `ProductGrid`, `ProductSkeletons` | Product listing UI | Retain domain-specific reuse within products `catalog/` |
| `ProductGallery` | Product details | Keep under products `details/`, rather than treating it as a generic image component |
| `apiClient` | Every feature API module | Retain the single shared HTTP client in `lib/` |
| `formatCurrency` | Customer and administration product UI | Retain shared formatting in `utils/` |
| `productCreation.js`, `productEditor.js`, `categoryLink.js` | Ordinary helpers without React hooks or state | Place under each owning feature's `utils/`; retain names and exports |

## Judgment calls and preserved behavior

- Auth has only three components, one hook module, and one API module, so its existing structure remains readable and does not need more folders.
- Admin hooks and APIs remain in place. No new public exports or subfolder barrels were added.
- Both admin and products root public APIs remain exactly the same; only their internal module paths changed.
- The Create wizard is rendered by `AdminProductEditor`, which still imports editor CSS at the same point. That stylesheet continues to style Create, Edit, shared form components, and the editor route page.
- `AdminProductList` still imports catalog CSS at the same point; the Products route heading still receives those global rules.
- Global CSS retains the original order: Tailwind, products catalog CSS, shared controls, storefront header, then the existing tokens and rules.
- Public image URLs and image provenance are unchanged. `public/` is maintained source material; `dist/` is generated by the production build and is not a source folder to reorganize.
- Existing auth/account rules remain within the global stylesheet. Splitting those rules, extracting components, or changing provider setup would exceed this import-only refactor.
- There is no Git metadata in this workspace. Filesystem moves were used following user authorization, with a pre-change snapshot and content comparison replacing Git rename review.
